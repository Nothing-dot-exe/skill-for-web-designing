## 🧭 The 6-Part Elite Personal Architecture

Generic prompts like *"Build me a personal developer portfolio"* guarantee generic 3-card templates with cartoon badges and *"Hi, I'm passionate about code"*. Top creative developers and design engineers enforce this structural framework:

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. PERSONA & AUTHORITY  → Specific discipline, no generic fluff        │
│ 2. SIGNATURE INTERACTION→ Particle canvas, CLI shell, or stem mixer    │
│ 3. NEGATIVE CONSTRAINTS → Ban generic gradients, fake buttons, cliches │
│ 4. DESIGN TOKENS        → Obsidian bases, 1px specular top borders     │
│ 5. FLUID TYPOGRAPHY     → Dynamic clamp() scale + editorial font pairs │
│ 6. RUNNABLE PROTOTYPE   → Standalone code for the hardest interaction  │
└────────────────────────────────────────────────────────────────────────┘
```

## ⚡ The Universal "Anti-Slop" Personal System Prompt

Paste this meta-prompt into Cursor, Antigravity, Claude, v0, or ChatGPT before building your personal site:

```markdown
Act as a Principal Design Technologist and Awwwards Jury Member specializing in world-class personal portfolios and founder monographs.
I want you to build [MY_PERSONAL_WEBSITE_TYPE] for [MY_NAME], [MY_DISCIPLINE].

CRITICAL NEGATIVE CONSTRAINTS (ZERO TOLERANCE):
- NEVER output greeting cliches: "Hi, I'm [Name], a passionate developer/designer who loves crafting intuitive experiences."
- NEVER use flat rectangular 3-card grids with generic GitHub/LinkedIn icons.
- NEVER use generic purple/blue linear gradients (#6366f1 to #a855f7). Use deep curated obsidian (#08080A / #050608) with high-contrast accent highlights.
- NEVER leave fake buttons or non-functional links. Every interactive trigger must perform a state update, modal open, or tactile audio click.
- NEVER use single-layer flat box-shadows. Use multi-layer diffused Bézier shadow falloff.

DESIGN SYSTEM DIRECTIVES:
- Color Tokens: Deep obsidian background, 1px borders with specular top highlight sheen (rgba(255,255,255,0.15)).
- Typography: Fluid clamp() scales. Heading: 'Syne' or 'Newsreader'. Body: 'Plus Jakarta Sans' or 'Inter'. Monospace: 'JetBrains Mono'.
- Interaction: Include a signature real-time mechanic (WebGL particle canvas, interactive CLI terminal, before/after slider, or soundboard).
- Micro-Interactions: Spring physics (cubic-bezier(0.16, 1, 0.3, 1)) on hover states and active button presses.
```

> [!WARNING]
> ### ⚠️ CRITICAL WARNING: READ EVERY PROMPT CAREFULLY BEFORE EXECUTING!
> **DO NOT blindly copy and paste these prompts without reading and customizing them!**
> 
> 1. **Replace Customization Variables:** Every blueprint includes explicit bracketed placeholders such as `[YOUR_NAME]`, `[CREATIVE_TITLE]`, `[LOCATION_TIMEZONE]`, `[FLAGSHIP_PROJECT]`, `[CURRENT_VENTURE]`, and `[CORE_THESIS]`. If you run a prompt without replacing these variables, the AI will either generate literal placeholder brackets or hallucinate an unrelated personal biography.
> 2. **Understand the Strict Negative Constraints:** Each blueprint contains a zero-tolerance negative constraint block designed to prevent AI slop (banning generic gradients, 3-card identical rows, fake non-functional buttons, and browser alerts). Review these constraints to make sure they align with your project's technical goals before sending.
> 3. **Verify Dependencies & Environment:** Certain blueprints feature advanced interactive mechanics (e.g. `Three.js` for WebGL shaders, `KaTeX` for mathematical proofs, `Web Audio API` for synthesized sound haptics). Verify that your project setup supports these technologies or specify your framework (e.g. Next.js, Vite, Vue, Svelte) at the top of the prompt.
> 4. **Iterate in Steps (Don't "One-Shot & Pray"):** The best vibe coding results come from phased execution: first prompt the layout and design tokens, then integrate the runnable starter code for the signature interactive mechanic, and finally run the QA verification checklist.
